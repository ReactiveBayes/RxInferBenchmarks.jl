# RxInferBenchmarks.jl
A dashboard of rxinfer performance metrics over time

## Static Dashboard

The dashboard is a static GitHub Pages site. `docs/index.html` is the page
template; the benchmark data is generated into `docs/data.js`.

Generate or refresh the dashboard data with:

```sh
make dashboard
```

Then open `docs/index.html` directly in a browser, or run:

```sh
make preview
```

`make preview` prints the local `file://.../docs/index.html` URL. No database,
server, JavaScript package manager, or build tool is required.

For GitHub Pages, set the repository Pages source to the `docs/` folder.

## Editable Files

Edit these files:

- `data/dashboard.toml`: metric definitions and benchmark navigation metadata.
- `data/records.csv`: benchmark measurements.
- `docs/style.css`: visual styling.
- `docs/dashboard.js`: dashboard behavior and layout.
- `docs/index.html`: static HTML shell.

Do not edit `docs/data.js` directly. It is generated by `make dashboard`.

`docs/data.js` still contains the data as JavaScript because it is the most
portable static-site format here: GitHub Pages can serve it, and opening
`docs/index.html` directly from disk still works without browser `fetch`
restrictions. The editable source of truth is `data/records.csv` and
`data/dashboard.toml`.

## Data Format

Each row in `data/records.csv` uses this order:

```text
date, commit, branch, julia, rxinfer, benchmark, scenario, metric, value
```

Example:

```csv
2026-05-01,cd9017e,main,1.12.6,dev,basic/coin_toss,"n=1k, iter=10",inference_ms,1.36
```

Rules:

- `benchmark` must match an `id` in `data/dashboard.toml`.
- `metric` must match an `id` in `data/dashboard.toml`.
- `scenario` is free-form text and becomes the scenario selector.
- Quote fields that contain commas, such as `"n=1k, iter=10"`.
- Each row is one metric value for one benchmark/scenario/date.

The chart always uses `date` on the x-axis. Commits are shown only in metadata,
recent-values tables, and point hover text.

## Adding Things

To add a benchmark, add a `[[benchmarks]]` block in `data/dashboard.toml`:

```toml
[[benchmarks]]
id = "basic/new_model"
category = "Basic Examples"
title = "New Model"
description = "Short human-readable description."
tags = ["basic", "example"]
```

Then add rows to `data/records.csv` using `basic/new_model` in the `benchmark`
column and run `make dashboard`.

To add a metric, add a `[[metrics]]` block:

```toml
[[metrics]]
id = "compile_ms"
label = "Compile"
unit = "ms"
lower_is_better = true
```

Then add rows to `data/records.csv` using `compile_ms` in the `metric` column
and run `make dashboard`.

The order of metrics and benchmarks in `data/dashboard.toml` controls the order
shown in the dashboard.

## Changing The View

The UI is intentionally small:

- `docs/index.html` controls the page regions.
- `docs/style.css` controls spacing, colors, and responsive layout.
- `docs/dashboard.js` renders navigation, filters, summary values, charts, and
  tables.

Useful places to edit:

- Metric overview layout: search for `renderMetricOverviewCharts` in
  `docs/dashboard.js`.
- Single chart rendering: search for `renderMetricChart`.
- Left navigation: search for `renderNav`.
- Overview card styling: search for `.overview-card` in `docs/style.css`.
- Main chart styling: search for `.chart` and `.axis-label`.

After UI changes, run:

```sh
make check-dashboard
```
